常见问题 ​

这一页收集配置与发布过程中最常见的疑问。按主题分组，遇到问题先在这里找。

安装与更新 ​

建议先卸载再安装

本插件迭代频繁。为避免程序缓存导致不可预知的问题，更新时请先卸载、再重新安装，不要直接覆盖。

配置异常导致插件完全不可用怎么办 ​

备份 [workspace]/data/storage/syp/sy-p-plus-cfg.json，然后删除它——这个文件会在首次使用时自动重新初始化。

操作时最好先关闭思源，删除配置后再打开，防止思源运行中已读取旧数据又把配置覆盖回去。

WARNING

插件能正常使用时不要做这个操作。

平台配置 ​

GitHub / GitLab 系平台有什么特别要求 ​

只支持源码部署。请确认你的仓库里存的是可构建的源码目录结构，而不是已构建的产物。

知乎和 CSDN 应该选哪种发布格式 ​

这两个平台目前只能选择 HTML 模式发布。在平台配置里把「发布格式」设为 HTML 即可正常使用。

知乎的专栏怎么获取 ​

  1. 打开知乎个人主页，找到你的用户名。
  2. 在插件配置页的「用户名」字段填入它。
  3. 点「验证」，通过后即可从专栏列表里选择。

CSDN / 知乎过一段时间提示「需要登录」 ​

这通常是 Cookie 过期。以 CSDN 为例：

  1. 安装「网页视图」插件，在思源内打开 CSDN 首页并退出登录。
  2. 回到插件配置页，重新授权。

TIP

必须在思源的网页视图里退出登录才有效，在外部浏览器退出不会同步。

知乎授权报 {"code":40362} 或提示请求异常 ​

知乎现在可以直接在插件内登录：配置页点「去登录」，在插件窗口里登录（支持扫码），关闭该窗口保存登录态，再点「自动读取 Cookie」。

只有在旧版插件上才需要手动复制 Cookie；若仍报这个错，先升级插件，再删除该平台账号重新导入。

CORS 代理怎么配置 ​

见插件内的「CORS 代理配置指南」。如果平台配置异常，先确认思源地址与端口填写正确（默认 127.0.0.1，本地使用）。

Docker 版初次打开显示不正常 ​

检查「偏好设置」里的思源地址是否包含端口。Docker 环境下填错地址会导致读不到数据。

发布行为 ​

每次发布都会覆盖正文

发布工具每次都会获取思源中最新编辑的正文进行覆盖发布。因此不要在平台上直接修改正文，改动会在下次发布时被覆盖。

各平台的图片是怎么处理的 ​

平台类型图片处理方式
知乎、CSDN、微信公众号使用平台自带上传
Notion、语雀、掘金需要配置图床（平台原生直传或自备图床）
GitHub 系、GitLab 系（Hexo 等）需要配置图床
MetaWeblog 系（博客园、Typecho、WordPress）图床与平台自带都支持；配了图床优先用图床

想强制用平台自带上传

卸载图床插件即可。知乎这类平台不支持外链，只能用它自己的上传。

源码模式里的图片还是本地路径，正常吗 ​

正常。源码模式显示的就是文档的原始 Markdown，图片的上传与链接替换在发布时进行。正文含图片时，可点提示条中的「上传并预览替换后的内容」提前查看替换效果——该操作会立即上传图片（与发布时的上传相同），预览内容不会写入文档，可随时点「恢复原文」切回。

掘金发布时提示缺少分类或标签 ​

掘金平台强制要求标签与分类。未显式设置时，插件会回退默认分类「后端」与默认标签「程序员」。

掘金发布后马上预览是 404 ​

掘金每篇文章都要审核。审核通过前可把链接里的 /post 临时改成 /spost 查看，或等审核通过。

CSDN 必须设置标签 ​

这是 CSDN 平台规定，标签不能为空。

博客园外链 404 或 H1 标题被替换 ​

  • 外链 404：可通过调整博客园用户配置解决。
  • H1 标题异常：多半是发布格式选错了。博客园请使用 Markdown，不要用 HTML。

Notion 为什么不支持更新 ​

Notion 基于块结构而非整篇文档。当前实现采用「先删除再发布」的方式支持更新，因此耗时可能比普通更新久一些。

微信公众号怎么登录 ​

可以直接在插件内登录：配置页点「去登录」，用公众号管理员微信扫码登录 https://mp.weixin.qq.com，关闭登录窗口保存登录态，再点「自动读取 Cookie」写入本账号。不需要手动复制 Cookie。

旧版插件才会提示只能复制 Cookie —— 升级后按上面的流程重新授权即可；登录过期或切换账号后同样重新走一遍。

发布记录 ​

平台上有文章，插件却显示「未发布」 ​

多半是文档 ID 变了。发布记录按思源的文档 ID 保存，以下操作会改变它：

  • 删除文档后重新创建
  • 拆分或合并文档
  • 从别的工作区导入

ID 一变，原记录就找不到这篇文档，于是显示「未发布」——但平台上的文章还在。

不要直接重新发布，那会产生重复文章。改用设置 → 发布修复把两边重新对上，做法见发布设置。

「发布修复」里的文章 ID 从哪里找 ​

打开平台上的那篇文章，地址栏里通常就带着它：

平台类型位置
多数博客平台地址栏里的数字或 slug
GitHub / GitLab 系仓库中该文章的路径或 slug
网页授权平台文章编辑页的地址栏

找不到也没关系：留空保存即可，原有记录不会被清掉，只是「查看文章」的链接可能不准。

删除了旧文章后想重新发布 ​

在文章管理里找到该文档，先「强制删除」清掉本地记录，再重新发布。这与「发布修复」是两件事：前者丢弃旧记录，后者把旧记录接回新文档。

菜单与入口 ​

菜单开关怎么用 ​

「顶栏菜单」开关实时生效；「文档菜单」需要重新加载插件或重开思源后生效。
