# Halo 网页版配置指南

通过 **Cookie 授权**发布到 **Halo 2.20+**。图片默认走「当前平台」（Halo 附件库）。

## 一、准备

1. 一个 Halo 2.20+ 站点（含后台登录账号）。
2. 在浏览器登录 Halo 后台。

## 二、配置

| 字段 | 填什么 |
|------|--------|
| 平台首页 | Halo 博客首页完整地址，如 `https://yourhalo.com` |
| API 地址 | 通常和首页地址相同 |
| Cookie | 点「1 去登录」登录后关闭窗口，再点「2 自动读取 Cookie」；也可展开「手动编辑」直接粘贴 |
| 预览规则 | 查看文章链接模板，默认 `/archives/{slug}` |
| 发布格式 | 默认 HTML |
| 图床 | 默认「当前平台」（Halo 附件库）；Halo 2.20+ 会跟随站点「文章附件存储策略」，本地存储或 S3 等对象存储均可；不需要上传图片时可选「不使用」 |

> ⚠️ 必须先填「平台首页」完整 URL，再点登录/读取 Cookie；否则会提示 `Invalid URL`。

## 三、验证与发布

1. 点「1 去登录」→ 自动打开 Halo 登录页 → 用后台账号登录 → **关闭窗口**（关闭时保存 Cookie）。
2. 点「2 自动读取 Cookie」→ 验证 → 账号状态「运行中」。
3. 快速发布 → 选 Halo网页版 → 发布。

## 四、题头图与图片复用

- 封面按「思源题头图链接 → 正文首图链接 → 自定义上传」的顺序解析；前两者直接使用链接，不额外上传图片。
- 题头图不会再出现在正文首图；发布表单里的「封面图」可填写链接或上传自定义图片，主动选择会优先于自动解析。
- 没有题头图、正文首图或自定义封面时，更新会保留 Halo 端现有封面。
- 正文图片按内容复用已上传的 Halo 附件：重复更新不会重复上传；图片内容变化或附件被删除时会重新上传。
- 图片上传跟随 Halo 站点的「文章附件存储策略」；切换到 S3 等对象存储后，重新发布会使用新的存储策略和对应图片地址。

## 常见问题

- **提示「Invalid URL」**：先填完整站点地址，再点登录/读取 Cookie。
- **Halo 版本要求**：需 2.20 及以上。
- **验证报「接口返回异常/登录状态可能已失效」**：Cookie 过期或 Halo 重启导致会话失效，重新登录读取 Cookie。
- **图片图床**：默认「当前平台」即可；需要与思源一致的图床时可改选 PicGo。
- **文章别名和站点设置不一致**：新建文章时会读取 Halo 的「别名生成策略」（按标题 / 时间戳 / Short UUID / UUID）生成默认别名；发布页手动修改的别名优先。更新已发布文章沿用原别名，避免链接变化。
