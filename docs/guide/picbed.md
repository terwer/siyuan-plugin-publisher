# 图床设置

图片先上传到图床，再把链接写进文章——这样平台侧拿到的是稳定可访问的图片地址。

图片的**上传与链接替换在发布时执行**；源码模式下可手动预览替换效果，文档本身不会被改动（见[详细发布](./single-publish)）。

## 三种方式

| 方式 | 说明 | 适合 |
|---|---|---|
| **平台原生直传** | 交给平台自己的图片服务处理 | 知乎、CSDN、微信公众号等强制使用自家服务的平台 |
| **内置图床** | 阿里云 OSS、腾讯云 COS 等，在插件里直接填密钥 | 有自己的对象存储，想统一管理图片 |
| **PicGo** | 连接本机运行的 PicGo 服务 | 已经用 PicGo 管理图床，或需要它的多图床能力 |

## 配置位置

设置 → **图床设置**。也可以在「偏好设置」里指定**默认图床**，各平台可单独覆盖。

## 平台原生直传的适用范围

| 平台 | 图片处理 |
|---|---|
| 知乎、CSDN、微信公众号 | 使用平台自带上传，外链不被接受 |
| Notion、语雀、掘金 | 需要配置图床 |
| GitHub 系、GitLab 系（Hexo 等） | 需要配置图床 |
| MetaWeblog 系（博客园、Typecho、WordPress） | 两者都支持；配了图床则优先用图床 |

::: tip 想强制用平台自带上传
卸载图床插件即可。反过来，想强制使用自己的图床，就卸载平台侧的图床插件。
:::

## 控制图片自动上传

从 2.4.0 起，可以按文章、目录或整个笔记本决定是否自动上传图片。

### 为单篇文章设置

在发布页找到「图片自动上传」：

- **跟随设置**：先检查目录排除规则，未命中时按平台图床设置处理。
- **自动上传**：覆盖目录排除规则，按平台图床设置处理图片；仍需配置可用的图床，不会强制更换图床服务。
- **不自动上传**：该文章发布到所有平台时均跳过图片自动上传。

选择后自动保存为文档属性，随思源文档同步；快速发布与批量分发也使用这项设置。

### 排除目录或整个笔记本

1. 打开「设置 → 图床设置」，找到「按目录排除自动上传」。
2. 选择笔记本，再选择一个目录或「整个笔记本」。
3. 添加规则。目录规则对所选目录文档及其全部子文档生效。

生效顺序为：**文章设置 > 目录排除规则 > 平台图床设置**。例如，目录已排除，单篇文章仍可选择「自动上传」作为例外。没有设置文章选项或目录规则时，继续使用原有的平台图床设置。

### 关闭上传后会怎样

- 正文图片、Confluence 页面图片、WordPress 特色图片以及源码模式的上传预览均遵循同一规则。
- 跳过上传时保留原图片链接，不删除思源本地资源；发布结果会提示跳过的本地图片数量。
- 源码模式显示「按设置不上传」，不提供上传预览入口。

::: warning 本地图片链接无法直接在远端显示
关闭自动上传后，文章中的 `assets/` 等本地路径会被保留。这些图片在远端平台可能无法显示；如需在远端展示，请开启自动上传并配置可用图床，或使用远端可访问的图片链接。
:::

## PicGo

使用 PicGo 需要本机已安装并运行 PicGo 服务（默认端口 `36677`）。

1. 安装并启动 [PicGo](https://github.com/Molunerfinn/PicGo)。
2. 在 PicGo 里配好至少一个图床。
3. 回到插件的「图床设置」，选择「PicGo 强烈推荐」，确认端口与密钥。

::: tip 挂件与扩展模式
PicGo 是本机服务，只有在插件能访问本机网络时才可用。浏览器扩展与网页版受同源策略限制，建议改用内置图床或平台原生直传。
:::

## 常见问题

### 图床配置不生效

先检查文章的「图片自动上传」选项与目录排除规则；按设置跳过上传时，保留本地路径是预期行为。如果允许自动上传，再确认图床服务正在运行，并检查端口、密钥与存储桶权限。

### 图片上传成功但文章里显示不出来

对象存储的**读权限**没开。多数对象存储默认私有读写，需要把读权限设为公共读，或配置 CDN 域名。
