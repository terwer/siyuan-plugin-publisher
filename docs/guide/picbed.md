# 图床设置

图片先上传到图床，再把链接写进文章——这样平台侧拿到的是稳定可访问的图片地址。

## 三种方式

| 方式 | 说明 | 适合 |
|---|---|---|
| **平台原生直传** | 交给平台自己的图片服务处理 | 知乎、CSDN、微信公众号等强制使用自家服务的平台 |
| **内置图床** | 阿里云 OSS、腾讯云 COS 等，在插件里直接填密钥 | 有自己的对象存储，想统一管理图片 |
| **PicGo** | 连接本机运行的 PicGo 服务 | 已经用 PicGo 管理图床，或需要它的多图床能力 |

## 配置位置

设置 → **图床设置**。也可以在「偏好设置」里指定**默认图床**，各平台可单独覆盖。

## 平台原生直传的适用范围

| 平台 | 图片处理 |
|---|---|
| 知乎、CSDN、微信公众号 | 使用平台自带上传，外链不被接受 |
| Notion、语雀、掘金 | 需要配置图床 |
| GitHub 系、GitLab 系（Hexo 等） | 需要配置图床 |
| MetaWeblog 系（博客园、Typecho、WordPress） | 两者都支持；配了图床则优先用图床 |

::: tip 想强制用平台自带上传
卸载图床插件即可。反过来，想强制使用自己的图床，就卸载平台侧的图床插件。
:::

## PicGo

使用 PicGo 需要本机已安装并运行 PicGo 服务（默认端口 `36677`）。

1. 安装并启动 [PicGo](https://github.com/Molunerfinn/PicGo)。
2. 在 PicGo 里配好至少一个图床。
3. 回到插件的「图床设置」，选择「PicGo 强烈推荐」，确认端口与密钥。

::: tip 挂件与扩展模式
PicGo 是本机服务，只有在插件能访问本机网络时才可用。浏览器扩展与网页版受同源策略限制，建议改用内置图床或平台原生直传。
:::

## 常见问题

### 图床配置不生效

确认图床服务正在运行，并检查端口与密钥是否正确。发布时如果平台侧图片是本地路径，说明图床没有生效，多半是密钥或存储桶权限问题。

### 图片上传成功但文章里显示不出来

对象存储的**读权限**没开。多数对象存储默认私有读写，需要把读权限设为公共读，或配置 CDN 域名。
