## ADDED Requirements

### Requirement: 平台配置帮助 SHALL 归一化动态实例 key

平台配置帮助系统 SHALL recognize dynamic platform instance keys generated by the existing platform model and normalize them to preset platform help configs before directory/global fallback.

#### Scenario: 动态语雀 API 实例命中预置帮助

- **WHEN** help registry receives `platform-config/common_Yuque-z2jom6d`
- **AND** `platform-config/common_Yuque` is registered
- **THEN** it SHALL return the `platform-config/common_Yuque` help config
- **AND** `getHelpUrl()` SHALL return the preset Yuque help URL

#### Scenario: 动态语雀网页版实例命中预置帮助

- **WHEN** help registry receives `platform-config/custom_Yuqueweb-z2jom6d`
- **AND** `platform-config/custom_Yuqueweb` is registered
- **THEN** it SHALL return the `platform-config/custom_Yuqueweb` help config

### Requirement: 平台 key 规范化 SHALL 复用 src/platforms SSOT

The normalization rule SHALL live with the existing platform key model in `src/platforms/dynamicConfig.ts`, not in a separate help-only matching utility.

#### Scenario: 从实例 key 获取子平台类型

- **WHEN** `getSubPlatformTypeByKey("common_Yuque-z2jom6d")` is called
- **THEN** it SHALL return `SubPlatformType.Common_Yuque`

#### Scenario: 预置 key 与实例 key 解析结果一致

- **WHEN** `getSubPlatformTypeByKey("custom_Zhihu")` and `getSubPlatformTypeByKey("custom_Zhihu-z2jom6d")` are called
- **THEN** both SHALL return `SubPlatformType.Custom_Zhihu`

### Requirement: 字段帮助与 tour SHALL 使用同一 fallback 链

Field and tour lookup SHALL use the same `HelpRegistry.get()` fallback chain as page-level help URL lookup.

#### Scenario: 动态实例 key 获取字段帮助

- **WHEN** `getField("platform-config/common_Yuque-z2jom6d", "token")` is called
- **AND** `platform-config/common_Yuque` defines field help for `token`
- **THEN** the preset platform field help SHALL be returned

#### Scenario: 动态实例 key 获取 tour

- **WHEN** `getTour("platform-config/custom_Yuqueweb-z2jom6d")` is called
- **AND** `platform-config/custom_Yuqueweb` defines tour steps
- **THEN** the preset platform tour SHALL be returned

### Requirement: Existing fallback behavior SHALL be preserved

Dynamic platform key normalization SHALL be additive. Existing exact page matches, directory `_default`, and global `_default` behavior MUST continue to work.

#### Scenario: 无预置平台配置时回到目录默认帮助

- **WHEN** help registry receives a `platform-config/<platformKey>-<id>` value without a registered preset platform config
- **THEN** it SHALL fall back to `platform-config/_default` if present

#### Scenario: 非平台配置页面不参与平台 key 规范化

- **WHEN** help registry receives a non-`platform-config/` page id
- **THEN** it SHALL keep existing exact/directory/global fallback behavior
