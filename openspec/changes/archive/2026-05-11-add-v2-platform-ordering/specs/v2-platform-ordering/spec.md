## ADDED Requirements

### Requirement: V2 账号列表必须启用优先并保留用户排序
V2 账号列表 MUST 使用确定性的展示顺序：已启用账号在前，未启用账号在后；同一启用状态分组内按用户持久化的平台展示顺序排列。历史账号没有显式排序字段时，必须继续可见，并且必须按它们在 `DYNAMIC_CONFIG_KEY.totalCfg` 中的原始相对顺序兜底，不得要求用户重新配置账号。

#### Scenario: 历史账号没有排序字段
- **WHEN** V2 账号列表加载到没有平台排序字段的历史 `DynamicConfig` 记录
- **THEN** 系统必须先显示已启用账号，再显示未启用账号
- **AND** 同一启用状态分组内必须保留原 `totalCfg` 相对顺序
- **AND** 系统不得仅因为计算了兜底顺序就写回设置

#### Scenario: 已启用和未启用账号混合存在
- **WHEN** V2 账号列表包含已启用账号和未启用账号
- **THEN** 所有已启用账号必须显示在所有未启用账号前面
- **AND** 未启用账号必须继续可见、可授权、可启用、可删除

#### Scenario: 用户调整账号顺序
- **WHEN** 用户在 V2 账号管理界面调整账号顺序
- **THEN** 新顺序必须持久化到对应账号配置中
- **AND** 该顺序必须在重新打开 V2、插件重载、设置页重新进入后保持
- **AND** 排序操作不得改变授权状态、启用状态、平台凭据、Cookie、metadata 或发布校验状态

#### Scenario: 用户排序后启用或停用账号
- **WHEN** 用户启用或停用一个已有排序的账号
- **THEN** 该账号必须移动到对应的已启用或未启用分组
- **AND** 它自己的持久化相对顺序必须继续保留

#### Scenario: 用户排序后新增或删除账号
- **WHEN** 用户在已有自定义顺序后新增账号
- **THEN** 新账号必须默认插入对应启用状态分组的末尾
- **WHEN** 用户删除一个已有排序的账号
- **THEN** 被删除账号不得继续影响剩余账号的展示顺序

### Requirement: V2 快速发布必须消费同一平台顺序
V2 快速发布 MUST 使用账号管理中同一份持久化平台展示顺序，保证用户在账号设置里配置的优先级能反映到快速发布入口。快速发布不得维护第二套独立排序数据。

#### Scenario: 快速发布展示已排序平台
- **WHEN** V2 快速发布加载多个已启用平台且这些平台存在持久化排序字段
- **THEN** 快速发布卡片必须按同一平台展示顺序渲染
- **AND** 该顺序必须与 V2 账号管理中已启用账号的相对顺序一致

#### Scenario: 快速发布存在被阻塞的已启用平台
- **WHEN** 一个已启用平台因未授权或发布校验失败而不可直接发布
- **THEN** 该卡片必须继续可见，并保留现有配置入口和 tooltip 原因
- **AND** 该卡片不得因为排序而变成可发布状态

#### Scenario: 快速发布加载无排序字段的历史账号
- **WHEN** V2 快速发布加载到没有排序字段的历史已启用账号
- **THEN** 它必须使用与 V2 账号管理一致的兜底顺序
- **AND** 它不得要求用户重新配置已有账号

### Requirement: V2 排序交互必须紧凑且可访问
V2 排序交互 MUST 符合当前紧凑的设置页视觉语言。账号管理界面必须提供明确但低噪声的拖拽手柄，并必须提供键盘可访问的兜底操作。

#### Scenario: 用户使用鼠标或触控板拖拽排序
- **WHEN** 用户拖拽 V2 账号列表中的排序手柄
- **THEN** 列表必须给出清晰的拖拽行和落点反馈
- **AND** 用户释放后必须持久化新的顺序
- **AND** 授权、管理、启停、删除等普通行内操作必须继续可点击，不能误触拖拽

#### Scenario: 用户不使用指针拖拽也能排序
- **WHEN** 用户通过键盘聚焦账号排序控件
- **THEN** 系统必须提供上移/下移或等价方式调整账号顺序
- **AND** 键盘调整后的持久化结果必须与拖拽排序一致

#### Scenario: 大量账号下排序控件仍保持紧凑
- **WHEN** 账号列表包含很多平台
- **THEN** 排序控件不得增加明显的大块垂直空间
- **AND** 账号状态、平台名称、平台 key、授权动作、启停开关、删除动作必须仍然清晰可扫读
